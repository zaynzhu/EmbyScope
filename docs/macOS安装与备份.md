# 映览 macOS：安装、升级与备份

此包为个人自用的 macOS 原生版本，要求 macOS 14 或以上。文件名中的 `arm64` 用于 Apple Silicon Mac；不是 NAS 的 linux/amd64 镜像。不需要另装 Node、Docker 或数据库。

## 安装

1. 双击 `EmbyScope-版本-arm64.dmg`。
2. 可以先直接双击映像内的 `EmbyScope.app` 查看；确定安装后，再拖入同窗口的 `Applications` 文件夹。
3. 若已安装，先退出映像内的应用，再弹出映像，从“应用程序”打开；若仅预览，查看完退出应用并弹出映像即可。

同一时间只运行一份应用。已有实例会被激活；如仍在项目目录运行开发版，请先正常退出它。

从 0.1.11 起，「服务器设置」的每台服务器下显示地址、反代、自动更新开关、轻量与完整校准周期、最近尝试读取时间，以及各类数据最后成功读取时间、错误和已有进度。在前台打开此页时，每 5 秒读取一次本地状态，不额外请求远端。连接状态来自上次读取结果，不是实时在线检测；尝试时间不代表成功，失败时仍可能展示旧缓存。这是最新状态展示，不是历史日志。

此包使用本机临时签名，**没有 Developer ID 分发签名和 Apple 公证**。本机运行测试不等于其他 Mac 的 Gatekeeper 验证。若系统阻止启动，请先核对来源与 SHA-256，再由你决定是否使用系统提供的“仍要打开”；不要关闭系统保护或批量移除隔离属性。正式跨机器分发仍需可用的开发者分发身份和公证条件。

从 0.1.10 起，Mac 版默认不要求启动密码，旧数据升级也默认直接进入首页。在「服务器设置 → 打开映览时需要密码」中开启：没有本机密码时设置并再次确认；已有密码时输入原密码确认。开启后下次启动或点击「锁定映览」需要解锁。关闭开关不会删除原密码，重新开启仍使用它。此设置仅影响 Mac 版，网页版继续要求管理员登录；连接凭据仍加密保存，本机辅助进程仍验证启动密钥。密码不是 Emby 账号密码。

从 DMG 直接运行正式 App 与安装后运行使用同一配置目录，不是隔离模式；可能按已有设置联网。单独提供的「离线预览.app」使用独立缓存副本并强制离线，设置修改不影响正式版本。

## 豆瓣已看

从 0.1.12 起，顶部「片库」后是「豆瓣已看」，支持按片名搜索、电影／剧集筛选、分页、评分与短评详情。它与服务器片库独立，切换 Emby 服务器不筛选豆瓣记录。

「服务器设置 → 豆瓣已看同步」提供账号、增量进度、全量／增量同步、停止和最近一次结果。默认不自动同步，不受服务器的 1 小时／24 小时更新控制，也无需运行 PixelReel。增量包含截止日期当天，成功后才推进日期；全量分页重读列表并补充空字段，不清空记录、不覆盖旧评分和短评。网页异常、重复页、访问验证或取消均保留原数据与进度。已有电影／剧集分类保留，豆瓣列表未给出可靠类型的新记录标为「未分类」。

记录、进度和已读取的海报均保存在映览自己的 SQLite 中，正常配置备份会一并包含。海报优先读缓存，缺失时按需限速下载；旧数据本身没有海报地址时显示占位，不自动启动全库补图。同步读取公开已看列表，不复制 PixelReel 的 Cookie、令牌或 Keychain 凭据；需要登录验证时明确报错，不自动绕过。

从 0.1.13 起，同步设置提供「补全缺失海报」和「停止补图」，显示待补、本地缓存、S3 镜像数量及最近任务结果。补图按豆瓣 ID 精确匹配，逐张下载保存；配置 S3 后将补全图片及现有本地缓存上传到 `embyscope/douban/豆瓣ID/内容哈希.扩展名`。补图和全量／增量同步互斥，补图不推进已看同步日期。中断后已保存图片保留，下一轮先处理未尝试条目；未匹配与下载／上传失败分别显示，不保证每个来源都能找到海报。

查找先使用 PixelReel 的建议接口精确 ID 匹配，未匹配时使用 WhatShot 的豆瓣详情路径补查海报；仅 404 才尝试另一媒体类型，身份不符、访问限制或异常响应立即停止，不自动重试绕过。之前未匹配的条目再次补图时直接查详情。普通浏览时新下载的海报也会尝试上传 S3；上传失败仍显示本地图片，设置页保留待上传数量，可通过补全入口重试。

S3 兼容存储沿用 WhatShot 的 path-style / SigV4，支持签名读取私有桶，不修改桶权限；本地缓存可离线读取。一次性工具 `scripts/import-whatshot-posters.mjs WhatShot配置目录 映览配置目录` 在退出映览后使用：将既有 S3 配置加密复制到映览，按唯一豆瓣 ID 复用旧对象引用，不修改 WhatShot 数据或对象。映览后续不依赖 WhatShot 运行；S3 密钥不经本机接口回传，备份时必须一并保留 `secret.key`。目前 S3 配置迁入使用此工具，界面只显示是否已配置。

开发侧一次性迁移工具为 `scripts/import-pixelreel.mjs`。先备份并正常退出映览，再运行：

```sh
node scripts/import-pixelreel.mjs \
  "/来源配置目录/PixelReel.sqlite" \
  "/映览配置目录" \
  "/旧海报缓存目录"
```

工具使用只读事务读取源库，校验账号绑定检查点、稳定豆瓣 ID、已看状态和待处理批次；完整验证后在目标事务复制。目标已有豆瓣记录时拒绝重复迁移，后续同步只访问豆瓣及映览副本。源数据库和旧应用保持不变。

## 配置与离线导入

配置目录：`~/Library/Application Support/EmbyScope/`。应用文件与数据分开保存。导入使用 SQLite 一致性备份，包含已提交的 WAL；不会改原网页配置，不会复制登录会话，并暂停自动更新。

导入产生的 `offline-preview` 文件强制离线：详情、海报及所有更新都不能访问远端。缺失海报显示占位，旧缓存继续标注时间。从 0.1.4 起，完成离线验证并决定允许远端读取后，在「服务器设置」点击「退出离线预览…」，确认即可，无需手动修改配置文件或重启。退出操作本身不请求服务器，自动更新仍保持关闭；手动更新、详情和缺失海报此后可能访问连接地址。受启动参数强制离线或演示模式不能在界面解除。

## 备份

建议升级前备份。内置命令支持应用运行时的一致性备份，目标必须是不存在的新目录；无需系统 Node。在 Mac 终端执行（路径可按实际安装位置调整）：

```sh
APP="/Applications/EmbyScope.app"
"$APP/Contents/Resources/runtime/node" \
  "$APP/Contents/Resources/service/desktop/backend/manage-data.js" backup \
  "$HOME/Library/Application Support/EmbyScope" \
  "$HOME/Documents/EmbyScope-backup-$(date +%Y%m%d-%H%M%S)"
```

备份含数据库和 `secret.key`。它们组合可以解密连接凭据，务必保护整个备份，不上传公开仓库。不复制实例锁，不依赖运行中的主数据库文件复制。

## 升级与恢复

升级：先备份，再正常退出映览（等待窗口消失），用新版本替换 `/Applications/EmbyScope.app`，最后重新打开。替换应用不会覆盖配置目录。

恢复：退出映览，将当前配置目录改名保留，再用下列命令从备份创建新的配置目录。目标已存在时命令会拒绝覆盖。

```sh
APP="/Applications/EmbyScope.app"
"$APP/Contents/Resources/runtime/node" \
  "$APP/Contents/Resources/service/desktop/backend/manage-data.js" import \
  "/你的备份目录" \
  "$HOME/Library/Application Support/EmbyScope"
```

恢复后进入离线预览、暂停自动更新并清除旧会话，先核对数据再决定是否允许联网。保留旧应用与对应备份才能可靠回退；不要假定未来版本的数据库可以直接由旧版本打开。

删除 `.app` 不删除数据。若要清理数据，请先做好完整备份。不要仅删除 `secret.key`，否则已有凭据将无法解密。
