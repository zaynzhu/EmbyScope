# 映览 · EmbyScope 部署说明

目标：极空间 Z4S，Intel x86_64，镜像平台固定为 **linux/amd64**。一个应用容器，SQLite 和密钥同目录持久化。不需要 SSH、systemd、Redis 或独立数据库。

## 一、云端取得镜像离线包

1. 在仓库的 **Actions → 构建并验证 amd64 离线包 → Run workflow** 选择要构建的分支。
2. 等待 `build` 和 `verify` 都通过。后者在另一台干净 runner 校验文件、导入镜像，并从包内 Compose 禁止拉取 / 构建启动，验证初始化、页面 API 和重启后持久化。
3. 下载 `embyscope-linux-amd64-verified` artifact，解压。包内包含 `images.tar`、`compose.yaml`、`compose.external-network.yaml`、`compose.env.example`、`manifest.json`、`SHA256SUMS`、`VERIFIED.json` 和校验文件。
4. `manifest.json` 记录镜像标签、镜像 ID、源码 commit 和 Actions 地址；`VERIFIED.json` 关联原包校验文件的 SHA-256 和实际验收范围。artifact 保留 30 天，请自行保存。校验和只证明完整性，不是签名。

这称为“镜像离线包”：启动不拉取依赖，但读取真实 Emby 时仍需要到对应服务器的网络连接。

## 二、极空间图形界面部署

1. 用极空间文件管理器建立专用配置目录，例如在自己选择的 Docker 数据目录下新建 `embyscope/config`。不要照抄他人的路径。
2. 在极空间 Docker 的镜像管理中选择导入本地镜像，选择包内的 `images.tar`。导入完成后应看到 `embyscope:<commit前12位>`。
3. 首选 Compose 项目功能：导入包内 `compose.yaml`，按页面支持方式设置环境变量，或将 `compose.env.example` 复制为 `.env` 与 Compose 放在同一目录。若界面不支持插值，将配置中的 `${...}` 在导入前替换为自己的具体值。
4. 至少设置 `EMBYSCOPE_IMAGE`、`APP_PORT` 和 `DATA_PATH`。`DATA_PATH` 必须是该 NAS 实际配置目录的绝对路径；不要挂载项目源码。镜像内固定监听 3000，宿主机端口可自选。
5. 默认容器 UID/GID 为 `1000:1000`。在极空间文件管理的权限设置中让配置目录对选定 UID/GID 可读写，或将 `PUID`、`PGID` 改为实际目录拥有者。若官方 UI 无法设置数字 UID/GID，可以在可信个人 NAS 上临时设为 `0:0` 启动；这降低了容器内权限隔离，建议后续恢复到可写目录的普通用户。无需给整个 NAS 目录开放权限。
6. 保持 bridge 网络启动项目。若用界面逐项创建容器：选同一镜像，将自己选定的宿主机端口映射到 TCP 3000，将配置目录挂载到 `/data`，设置重启策略为自动重启，并配置相同环境变量。不要启用特权模式或 host 网络。
7. 访问 `http://<NAS地址>:<你设置的端口>`。首次设置至少 12 字符的本地管理员密码，再添加 Emby 账号。没有默认管理员密码。

部分极空间固件的 Compose 页面及字段名称可能不同；没有对你的 NAS 做实际操作。按上述镜像、端口、挂载和环境变量映射即可，不依赖终端命令。

## 三、可配置参数

| 参数 | 默认值 | 含义 |
|---|---|---|
| EMBYSCOPE_IMAGE | 包内自动填入 | 必须与导入镜像标签一致 |
| APP_PORT | 3000 | 宿主机访问端口 |
| BIND_ADDRESS | 0.0.0.0 | 宿主机监听地址 |
| DATA_PATH | 必填 | NAS 配置目录绝对路径 |
| PUID / PGID | 1000 / 1000 | 容器运行用户 / 组，需能写挂载目录 |
| CACHE_MINUTES | 60 | 新连接的轻量更新默认间隔，15～1440 分钟；已有连接在服务器设置中调整，完整片库默认每天校准 |
| REQUEST_INTERVAL_MS | 2000 | 同 origin 请求最小间隔，不能低于 2000 |
| REQUEST_TIMEOUT_MS | 12000 | 单次请求超时，限制 1000～60000 |
| REQUEST_RETRIES | 1 | 网络错误、429、5xx 的有限重试，最大 2 |
| COOKIE_SECURE | false | 使用 HTTPS 访问映览时设 true；HTTP 设 true 会无法保持登录 |

没有容器 `env_file`；上述 `.env` / `compose.env` 用于 **Compose 插值**，由 `environment` 显式传入相应应用参数。不要把 Emby 密码写进这个文件。应用启动时会在 `/data` 首次生成 0600 密钥和数据库。

## 四、复用已有 bridge 网络

默认 Compose 自动创建独立 bridge 网络。如果已有网络可用，额外叠加 `compose.external-network.yaml`，设置 `EXISTING_NETWORK` 为真实网络名。或者在极空间 Docker 页面直接选择已有 bridge 网络。

如果界面只接收一个 Compose 文件，将主文件最下方替换为：

```yaml
networks:
  media:
    external: true
    name: 你实际存在的bridge网络名称
```

不要将不存在的网络名填为 external，Docker 不会自动创建它。网络名、NAS 地址和目录均未硬编码进应用。

## 五、备份、升级和回滚

- **备份**：先停止映览容器，再复制整个配置目录，包括 `secret.key`、`embyscope.sqlite` 以及仍存在的 `-wal` / `-shm` 文件。密钥和数据库必须配套备份；备份应保持访问限制。
- **升级**：备份后导入新 `images.tar`，将 `EMBYSCOPE_IMAGE` 改为新清单中的标签，再重建容器，保留 `/data` 挂载。启动后检查健康状态与缓存时间。
- **回滚**：停止容器，恢复升级前整套配置目录与对应旧镜像标签。不要只换旧镜像读取未来版本数据库；未来迁移不保证向后兼容。
- **密钥丢失**：有数据库但缺失密钥时应用拒绝启动；恢复完整备份。不能从密文恢复 Emby 密码。
- **忘记本地管理员密码**：本版本无网络重置接口。可停止容器、备份后使用新的空配置目录重新初始化并重新添加连接；原目录不要删除，保留恢复可能。
- **账号变化**：在服务器设置中编辑，保存后清空这个连接旧缓存再同步。只改名称会保留数据。删除只删除本地配置和缓存，不删除远端媒体、不撤销远端其他会话。

## 六、健康检查与排错

容器健康接口为 `/health`。健康通过仅代表应用进程可访问，不代表所有 Emby 在线。每台 Emby 的状态、错误和各区块缓存时间在服务器设置单独查看。

- 显示“不可用”：接口没有权限、版本不支持或未成功同步；不是零条数据。
- 显示“离线 / 旧缓存”：连接失败后保留上次完整结果；恢复网络后手动同步。
- 401：检查账号密码；过期令牌会清除，下次同步重新登录。403：该账号无权限，不尝试绕过。
- 404：检查完整 Emby 基地址及反向代理路径。服务端跳转不会自动跟随，避免凭据跨站转发。
- 初始化慢：首次同步逐页读取，海报也受 2 秒间隔约束；可以先浏览已完成的缓存。
- EACCES 或数据目录不可写：检查挂载路径和 PUID/PGID，勿通过删除配置目录处理。
- SQLite 实验性提示：Node.js 22 内置 SQLite 的正常提示；运行时已固定为 22.22.2。

## 可选：有终端的普通部署机

以下命令只给有终端的目标机器使用，极空间无需执行：

```sh
sha256sum -c SHA256SUMS
sha256sum -c VERIFIED.sha256
docker load --input images.tar
cp compose.env.example compose.env
chmod 600 compose.env
# 编辑 compose.env：镜像标签、端口、目录与运行用户。
docker compose --env-file compose.env config --quiet
docker compose --env-file compose.env up -d --pull never --no-build
# 复用已有网络时：
docker compose --env-file compose.env -f compose.yaml -f compose.external-network.yaml up -d --pull never --no-build
```

本项目没有在 NAS 执行构建、SSH 或 systemd 操作。云端验收不等同于真实 Emby 或 NAS 实机验收。
