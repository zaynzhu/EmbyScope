# 桌面可选启动密码：实现前自审

## 🔴 致命弱点

简单删除共享后端的登录校验会同时开放网页版，以及使本机任意网页能访问缓存和凭据相关操作。必须把免密码限定在带有效启动密钥的桌面进程；密钥、Host、来源校验依然先执行。最终实现满足此边界。

## 🟡 主要缺陷

- 仅在 Swift 隐藏登录页不能让后端正确授权，也不能在重启后保持开关。
- 开启时不先验证原密码，可能把使用者锁在自己不知道密码的应用之外。
- 预览直接使用真实在线配置可能发出海报或自动更新请求。

## 🟢 改进建议

- 在 SQLite settings 单独保存 desktopPasswordRequired，缺省 false（包括旧桌面配置）；网页版忽略该开关。
- 开启时新建密码或核对原密码，失败不修改状态；沿用口令哈希和有限次尝试。关闭保留密码，切换清除旧登录会话并签发当前会话，未解锁不能关闭已启用的锁。
- 首次设置在界面要求重复输入；免密码时隐藏手动锁定。独立预览复制本地缓存、强制离线并保留正式安装与数据。

## 📋 审查总结

边界可成立，最高优先级是验证桌面密钥与网页认证都没有被免密码绕过。不开这些边界会使本地便利设置变成全局认证降级。用户已明确授权桌面默认免密码；本地密码锁不承诺抵抗能够读写当前 macOS 用户配置文件的人。
