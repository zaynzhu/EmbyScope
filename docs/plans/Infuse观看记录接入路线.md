# Infuse 观看记录接入路线

日期：2026-10-24。项目基线：`7e1f618`，映览 0.1.17/build 18。状态：可行性研究与首阶段验证路线；未实现接入，未读取用户 Trakt 账号，未验证真实同步。

## 目标与推荐判断

用户在 Apple TV 使用 Infuse，已登录 Trakt；希望映览显示最近观看、已看状态和续播进度，不要求逐次完整观看历史，也不打算打开 Mac 上的 Infuse。片源可能混用 Emby／极影视、SMB 或 WebDAV，目前未确认。

推荐先验证 **Apple TV Infuse → Trakt → 映览**。映览使用自己的 Trakt 应用身份，经用户授权后读取数据，不依赖 Mac Infuse 进程或它的本地缓存。用户已确认的是目标与设备，正式产品实现、授权方式及展示入口仍未拍板。

成立前提：Apple TV 的 Infuse 已启用 Scrobbling，账号授权有效，记录和进度确实已上传。登录 Trakt 本身不能证明这些前提成立。Mac Infuse 不需要打开；尚未上传的 Apple TV 本地数据不能凭空读取，也不能保证补回历史上从未同步的记录。

## 已核实依据

本轮使用 Tavily 定位官方资料，再读取 Firecore 官方文档与 Trakt 官方 API 合约。只做公开资料和本项目代码研究，没有启动 Infuse、读取其私有数据库、连接 NAS 或操作 Trakt 账号。

| 依据 | 结论与适用范围 |
| --- | --- |
| [Firecore：Trakt Sync](https://support.firecore.com/hc/en-us/articles/4405098078743-Trakt-Sync)，页面更新于 2026-05-06 | 支持观看历史、未完成条目的播放位置；要求登录 Trakt 并启用 Scrobbling。是否真实上传要按用户账号验证。 |
| [Firecore：媒体服务器连接](https://support.firecore.com/hc/en-us/articles/360006462093-Streaming-from-Plex-Emby-and-Jellyfin)，页面更新于 2026-05-29 | 使用媒体服务器连接播放时可向服务器和 Trakt 同步观看与进度；Infuse 对该连接的已看状态以媒体服务器为准，不从 Trakt 反向拉取已看历史。 |
| [Trakt 官方同步合约](https://github.com/trakt/trakt-api/blob/master/projects/api/src/contracts/sync/index.ts) | 提供经 OAuth 认证的观看历史、已看及播放进度读取入口；进度按最近暂停排序。合约是接口依据，不等于用户实测结果。 |
| [Trakt 进度字段](https://github.com/trakt/trakt-api/blob/master/projects/api/src/contracts/sync/schema/response/playbackItemResponseSchema.ts) | 包含 `progress`（0–100）、`paused_at` 和记录 `id`；这是进度快照，不是本机文件的秒级播放位置。 |
| [本项目首页](../../src/home.js)、[条目规范化](../../src/identity.js) | 首页从 `catalog/latest/resume` 缓存读取每条目的最后播放时间；规范化保留 `PlaybackPositionTicks`、`LastPlayedDate`，未保留 `Played`。现有最近观看不是 Infuse 专属记录，也不是完整观看历史。 |

旧 Apiary 文档入口本轮返回 502，未将其视为接口失效；改用官方仓库合约。Tavily 的自动摘要曾将整页其他方法的 VIP 提示混入进度查询结论，未据此判断进度读取必须付费。收费限制、应用权限、分页行为以实施时最新官方文档和实际账号响应为准。

## 数据含义与最小范围

| 用户需要 | 候选读取入口 | 展示含义与限制 |
| --- | --- | --- |
| 最近观看 | `GET /sync/history`，并结合进度条目的 `paused_at` | 历史反映已记录的观看事件；未完成条目按最近进度更新时间另列，不能把 `paused_at` 改叫观看完成时间。具体筛选路径和分页须在授权后核验。 |
| 已看状态 | `GET /sync/watched/movies`、`GET /sync/watched/shows` | 按电影／单集保留状态；看过一集不代表整部剧看完。历史第一页不足以还原全量已看状态。 |
| 续播进度 | `GET /sync/playback` | 显示百分比和最近同步时间，不伪造“正在播放”。不同剪辑版时长不同，不能把作品进度直接当某个文件的精确秒数。 |

第一版建议作为独立的 Trakt 来源展示，读取最近记录和续播，已看按覆盖范围显示。先不与 Emby 或豆瓣自动合并，也不写回远端状态。Trakt 记录可能混合其他播放器和手动标记；在没有来源证据前不能命名为“Apple TV Infuse 专属历史”。

媒体身份使用 Trakt／TMDB／IMDb 等稳定编号及影视类型；单集必须有单集身份或剧集身份加季集号。无法匹配本机片库的条目仍可单独展示，不按标题强行关联。重复读取应幂等；重新观看时允许“曾看完”和“当前有进度”同时成立。

## 首个可执行阶段：只验证真实数据来源

前置条件：用户决定继续验证，具有自己 Trakt 账号的授权入口；为映览配置独立 Trakt API 应用身份。用官方 OAuth 流程授权，不提取 Infuse 的令牌，不让用户在聊天粘贴密码或令牌。具体客户端类型、回调与令牌续期按实施时官方能力选择，不能把发行 App 内的公共客户端凭据当作秘密。

1. 先核对一个用户认可的已看条目，以及一个未看完条目是否已到 Trakt。网页可用于确认已看，但不能替代播放进度 API 的字段验收；无需打开 Mac Infuse。
2. 授权后用隔离诊断读取少量历史、电影／剧集已看和播放进度，保留脱敏计数、更新时间、字段及错误码。所有 Trakt 请求共用 `RateLimiter`，间隔不少于 2 秒；429 遵守服务端退避，不并行扫库。
3. 对照这两个样本的身份、已看语义与进度。若既有数据足够，先确认读取能力；只有需要检验新变化时，才由用户在 Apple TV 正常播放／暂停一次，再观察 Trakt 更新。测试本身会产生真实观看状态，不自动替用户播放或标记。
4. 通过后再确定首版界面和缓存实现范围。授权令牌保存在受保护的本机存储；不进入 Git、URL、日志或对前端的普通状态响应。本阶段没有正式数据库迁移。

验收必须分别给出结果：已看条目是否正确、未完成条目是否有进度、新变化是否能同步。只有历史而无进度时，报告“最近已看可用、续播未验证”，不能宣布全部接通。空响应只说明该次没有返回记录，不能直接归因未观看或全已看完。

如果记录不在 Trakt，先核对 Apple TV 的 Scrobbling、账号绑定、影片识别及同步错误，不改映览展示来掩盖上游缺口。若只在媒体服务器有状态，再确认连接类型与同一用户身份，评估服务器读取；SMB/WebDAV 场景不能据此假设存在 Emby 回写。

## 后续工程边界

验证通过后才新增 Trakt 客户端、凭据生命周期、本机缓存与原生展示。可复用 [RateLimiter](../../src/emby.js) 和 [本机加密能力](../../src/store.js)，但不得复用 Emby 的远端身份或把 Trakt 对象硬塞进服务器条目结构。

实际读取记录使用 GET；OAuth 换取／刷新令牌属于必要认证操作。产品承诺只读须由请求白名单保证，不能未经核实宣称 Trakt 授权本身只有只读权限。失败保留带时间的旧缓存；账号切换须隔离数据，未获取完整分页不能覆盖全量已看集合。使用前重新核对官方分页、删除与撤销标记语义。

这一阶段暂不要求跨来源去重、实时在播、自动控制 Infuse、iCloud 私有数据接入、历史补造或向豆瓣／Emby 回写。若用户后来要求其中任一项，需要重新审查业务含义和范围。

## 对推荐路线的对抗性自审

### 🔴 致命弱点

“已登录 Trakt”不等于“可取得用户所需的数据”。如果没有开启 Scrobbling、授权失效或条目无法识别，整条来源链就没有数据。官方能力只能证明支持，不能替代真实样本；因此先做来源验证，尚不进入完整产品开发。

### 🟡 主要缺陷

| 缺陷 | 后果 | 处理 |
| --- | --- | --- |
| 同一账号混合多个播放器 | 将其他来源误标为 Infuse | 标注 Trakt 来源，不推断设备归属 |
| 历史与进度的时间语义不同 | 未看完被误当已看、暂停被当实时播放 | 分开状态、时间和展示名称 |
| 只有最近历史或部分分页 | 老记录被误标未看、缓存被清空 | 明示覆盖；完整分页后才替换对应集合 |
| 稳定编号缺失或多剪辑版本 | 错配影视、进度对应错误文件 | 独立展示，匹配不足不自动合并 |

### 🟢 改进建议

先读真实已看与进度两个样本，再用独立 Trakt 来源接入；保留更新时间和失败状态。用户目标不要求逐次历史，不建设无必要的事件仓库。若用户要求精确到 Infuse 或特定 Apple TV，先取得来源字段证据，再决定能否满足。

### 📋 审查总结

技术路线有官方依据，账号实际覆盖尚未验证。最高优先级是确认同步数据；若跳过，会把上游缺记录误当成映览接入问题。自审由主 agent 完成，未启动子 agent。

## 接手约定

执行前核对目标、设备、Mac Infuse 不启动约束、当前代码、授权状态和上述首阶段验收。普通细节自行查证，局部可逆调整允许记录后执行；本路线本身不授权登录账号、迁移数据或完整产品开发。

缺少数据／工具时标记受阻；进入未知区域先说明证据与选择。需要变更数据来源、写回远端、读取 Infuse 私有凭据、合并身份或扩大为完整工程时，交回确认范围。前提被反证时停止受影响路线，提交预期、实际、复现证据、已尝试项、受影响假设及待决定问题，不降低验收标准。

可转发启动指令：阅读 `docs/plans/Infuse观看记录接入路线.md`，作为执行者先核对授权与首阶段条件，仅完成获授权的 Trakt 数据来源验证。保持 Mac Infuse 关闭，按文档分别报告已看与续播结果、来源覆盖和剩余未知，再交回确定产品实现范围。
