# Infuse 观看记录接入路线

初稿：2026-10-24；更新：2026-10-26。初稿基线：`7e1f618`，已安装版映览 0.1.17/build 18。当前状态：用户已授权继续实现；本地接入代码和模拟验证已完成，真实账号授权与同步尚未通过，未发布新版安装包。

## 当前进展与阻塞

- 已新增独立 Trakt 原生页面：最近已看、全部已看、继续观看，支持搜索、类型筛选、分页、手动同步、停止、重新授权和清除本机缓存。
- 设备码授权只需要 Client ID。OAuth 请求发往 `auth.trakt.tv`，资料读取发往 `api.trakt.tv`；使用映览独立令牌，不复用 PixelReel 或 Infuse 的现有令牌。所有远端请求共用至少 2 秒间隔的 RateLimiter，并遵守 Retry-After。
- 令牌加密保存；刷新令牌单次使用，先保存新令牌再继续请求。只读白名单限制观看数据请求为 GET；失败保留旧缓存，完整分页及全部集合成功后原子提交；重新授权核实身份后清除旧账号缓存。
- 用户希望复用 PixelReel 注册信息，允许只读相关 `.env`。旧 Client ID 请求设备码返回 HTTP 401 / `invalid_client` / `client not found`，公共 API 返回 403。未修改原项目配置，未复制 Client Secret 或既有令牌。
- 曾误用浏览器已有的另一个账号查看应用页；用户纠正后停止账号操作并核对正确账号。正确账号由用户确认且已在页面验证，但用户名与私人凭据不落入本文件。当前应用列表为 0，GitHub 尚未连接。旧应用消失原因未知；[官方仓库同类讨论 #898](https://github.com/trakt/trakt-api/discussions/898)不能证明这个账号遭遇相同原因。
- 用户此前已允许绑定 GitHub 并创建映览应用。继续此路径时 GitHub 的授权按钮保持禁用，自动点击未完成绑定，已请用户手动完成。**没有创建新应用，没有获得设备码或令牌，没有读取真实观看记录。**
- 本地验证：Node 120 项测试、Swift 40 项测试通过；原生构建成功。独立预览副本使用新 bundle 标识、独立数据目录、模拟 Trakt 响应并禁止真实 fetch，实际核对了最近已看翻页、单集、进度百分比及筛选空状态；未覆盖正式 App 或配置。模拟成功不等于真实接通。

## 目标与推荐判断

用户在 Apple TV 使用 Infuse，已登录 Trakt；希望映览显示最近观看、已看状态和续播进度，不要求逐次完整观看历史，也不打算打开 Mac 上的 Infuse。片源可能混用 Emby／极影视、SMB 或 WebDAV，目前未确认。

接入方向为 **Apple TV Infuse → Trakt → 映览**。映览使用用户注册的 Trakt 应用身份，经独立授权后读取数据，不依赖 Mac Infuse 进程或它的本地缓存。用户已授权继续实现；真实来源验收仍须完成。

成立前提：Apple TV 的 Infuse 已启用 Scrobbling，账号授权有效，记录和进度确实已上传。登录 Trakt 本身不能证明这些前提成立。Mac Infuse 不需要打开；尚未上传的 Apple TV 本地数据不能凭空读取，也不能保证补回历史上从未同步的记录。

## 数据含义与最小范围

| 用户需要 | 候选读取入口 | 展示含义与限制 |
| --- | --- | --- |
| 最近观看 | `GET /sync/history`，并结合进度条目的 `paused_at` | 历史反映已记录的观看事件；未完成条目按最近进度更新时间另列，不能把 `paused_at` 改叫观看完成时间。具体筛选路径和分页须在授权后核验。 |
| 已看状态 | `GET /sync/watched/movies`、`GET /sync/watched/shows` | 按电影／单集保留状态；看过一集不代表整部剧看完。历史第一页不足以还原全量已看状态。 |
| 续播进度 | `GET /sync/playback` | 显示百分比和最近同步时间，不伪造“正在播放”。不同剪辑版时长不同，不能把作品进度直接当某个文件的精确秒数。 |

第一版建议作为独立的 Trakt 来源展示，读取最近记录和续播，已看按覆盖范围显示。先不与 Emby 或豆瓣自动合并，也不写回远端状态。Trakt 记录可能混合其他播放器和手动标记；在没有来源证据前不能命名为“Apple TV Infuse 专属历史”。

媒体身份使用 Trakt／TMDB／IMDb 等稳定编号及影视类型；单集必须有单集身份或剧集身份加季集号。无法匹配本机片库的条目仍可单独展示，不按标题强行关联。重复读取应幂等；重新观看时允许“曾看完”和“当前有进度”同时成立。

## 尚待完成：真实数据来源验证

前置条件：完成正确账号的开发者绑定并取得有效的应用 Client ID。账号操作和创建应用已有用户授权，不应重复询问同一许可。通过设备码授权映览，不提取 Infuse 的令牌，不让用户在聊天粘贴密码或令牌。

1. 先核对一个用户认可的已看条目，以及一个未看完条目是否已到 Trakt。网页可用于确认已看，但不能替代播放进度 API 的字段验收；无需打开 Mac Infuse。
2. 授权后用隔离诊断读取少量历史、电影／剧集已看和播放进度，保留脱敏计数、更新时间、字段及错误码。所有 Trakt 请求共用 `RateLimiter`，间隔不少于 2 秒；429 遵守服务端退避，不并行扫库。
3. 对照这两个样本的身份、已看语义与进度。若既有数据足够，先确认读取能力；只有需要检验新变化时，才由用户在 Apple TV 正常播放／暂停一次，再观察 Trakt 更新。测试本身会产生真实观看状态，不自动替用户播放或标记。
4. 用已实现界面检查真实数据，逐项记录通过或失败。授权令牌保存在受保护的本机存储，不进入 Git、URL、日志或普通状态响应。真实验收完成后再制作新版 App/DMG，按安装与备份流程交付。

验收必须分别给出结果：已看条目是否正确、未完成条目是否有进度、新变化是否能同步。只有历史而无进度时，报告“最近已看可用、续播未验证”，不能宣布全部接通。空响应只说明该次没有返回记录，不能直接归因未观看或全已看完。

如果记录不在 Trakt，先核对 Apple TV 的 Scrobbling、账号绑定、影片识别及同步错误，不改映览展示来掩盖上游缺口。若只在媒体服务器有状态，再确认连接类型与同一用户身份，评估服务器读取；SMB/WebDAV 场景不能据此假设存在 Emby 回写。

## 后续工程边界

现已新增 Trakt 客户端、凭据生命周期、本机缓存与原生展示，复用 [RateLimiter](../../src/emby.js) 和 [本机加密能力](../../src/store.js)。缓存独立存放于 `trakt_cache`；没有复用 Emby 的远端身份或把 Trakt 对象硬塞进服务器条目结构。

实际读取记录使用 GET；OAuth 换取／刷新令牌属于必要认证操作。产品承诺只读须由请求白名单保证，不能未经核实宣称 Trakt 授权本身只有只读权限。失败保留带时间的旧缓存；账号切换须隔离数据，未获取完整分页不能覆盖全量已看集合。使用前重新核对官方分页、删除与撤销标记语义。

这一阶段暂不要求跨来源去重、实时在播、自动控制 Infuse、iCloud 私有数据接入、历史补造或向豆瓣／Emby 回写。若用户后来要求其中任一项，需要重新审查业务含义和范围。

## 对推荐路线的对抗性自审

### 🔴 致命弱点

“已登录 Trakt”不等于“可取得用户所需的数据”。有效应用身份、正确账号及实际上传均为必要前提；旧 Client ID 已被服务拒绝，当前真实来源验收受阻。用户要求继续后已完成独立实现，但不能把模拟测试全绿当作来源通过。

### 🟡 主要缺陷

| 缺陷 | 后果 | 处理 |
| --- | --- | --- |
| 同一账号混合多个播放器 | 将其他来源误标为 Infuse | 标注 Trakt 来源，不推断设备归属 |
| 历史与进度的时间语义不同 | 未看完被误当已看、暂停被当实时播放 | 分开状态、时间和展示名称 |
| 只有最近历史或部分分页 | 老记录被误标未看、缓存被清空 | 明示覆盖；完整分页后才替换对应集合 |
| 稳定编号缺失或多剪辑版本 | 错配影视、进度对应错误文件 | 独立展示，匹配不足不自动合并 |
| 浏览器沿用其他账号 | 将错误应用列表当作用户账号证据 | 每次授权前明确核对账号；本次纠正后的列表重新验证 |
| 模拟响应滞后于官方契约 | 测试全绿但真实接口没有 seasons | 已核实新分页和 `extended=progress`，保留真实验收门槛 |

### 🟢 改进建议

先解决正确账号的应用身份与授权，再核对真实已看与进度两个样本；保留更新时间和失败状态。用户目标不要求逐次历史，不建设事件仓库。若用户要求精确到 Infuse 或特定 Apple TV，先取得来源字段证据，再决定能否满足。

### 📋 审查总结

技术路线有官方依据，独立实现已通过模拟验证，账号实际覆盖尚未验证。最高优先级是取得有效应用身份后确认同步数据；若跳过，会把上游缺记录误当成映览接入问题。自审由主 agent 完成，未启动子 agent。

## 接手约定

继续前核对目标、设备、Mac Infuse 不启动约束、当前代码、正确账号与应用身份。复用会话中已有授权；本文件不能替代用户授权。不要因旧记录写着“先验证再实现”而忽略后续用户明确要求继续实施。

缺少数据／工具时标记受阻；进入未知区域先说明证据与选择。需要变更数据来源、写回远端、读取 Infuse 私有凭据、合并身份或扩大为完整工程时，交回确认范围。前提被反证时停止受影响路线，提交预期、实际、复现证据、已尝试项、受影响假设及待决定问题，不降低验收标准。

可转发启动指令：阅读本文件，保留现有实现与测试，继续完成正确账号的应用注册、独立设备码授权和真实数据验收。保持 Mac Infuse 关闭，分别报告已看与续播结果、来源覆盖及未验证项；真实通过后再交付新版安装包。
