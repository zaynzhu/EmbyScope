# Infuse 观看记录接入路线

初稿：2026-10-24；更新：2026-10-27。初稿基线：`7e1f618`；本路线的 Trakt 功能交付基线：映览 0.1.21/build 22，不代表整个应用的最新版本。独立授权、观看同步、首页与列表海报、账号配置入口已交付；0.1.21 增加独立自动同步开关，具体交付验证见验收记录。操作以[使用说明](../macOS使用说明.md#0120账号配置与导航)为准，分版本测试、真实快照和安装核验见[验收记录](../macOS验收记录.md)。

## 当前进展与验证边界

- 首页展示最近已看与续播海报，各最多 8 部作品，同剧保留最新一集，可切换服务器记录；完整 Trakt 页面保留单集、搜索、类型筛选和分页，支持手动同步与停止。0.1.21 可独立开启自动同步（默认关闭），启动或回到前台首页时检查 30 分钟间隔，失败冷却及限流跨重启保留。
- 「Trakt 观看 → 账号与配置」集中展示实际账号、授权状态、同步时间与数据来源，管理重新授权、切换及断开；应用配置与海报来源分别展开。「服务器设置」位于导航最后。
- 设备码只需 Client ID。OAuth 发往 `auth.trakt.tv`，资料读取发往 `api.trakt.tv`；使用映览独立令牌，不复用 PixelReel 或 Infuse 的 Trakt 凭据。同服务请求至少间隔 2 秒，并遵守 Retry-After。令牌加密保存，刷新轮换后先保存新令牌；观看请求受 GET 白名单限制，完整分页与全部集合成功后原子提交，失败保留旧快照。
- 旧 PixelReel Client ID 曾返回 HTTP 401 / `invalid_client` / `client not found`；浏览器还曾登录错误账号。核对正确账号、重新查找后仍未找到可用旧应用，用户于 2026-10-26 完成 GitHub 绑定、同意条款并注册「映览 EmbyScope」，随后批准并完成设备码授权。旧应用消失原因未知，不能根据其他账号或同类讨论推断。
- 海报优先使用已配置的 TMDB，按作品 ID 匹配并缓存本机；未配置时使用 Trakt 图片。TMDB 凭据在用户授权下从既有配置读取，独立加密保存，与 Trakt 授权分开维护，未修改 PixelReel 原配置。真实首页 14 张不同作品海报及离线显示已验收，不代表全量已看都有图。失败路径及复用方法见[Trakt 接入经验](../lessons/trakt-sync-posters.md)。
- 正确账号的三个观看集合、正式 App 手动同步及界面显示已验证；Apple TV 新播放上传延迟、设备归属与真实令牌到期后的长期续期仍未实测。刷新轮换有模拟覆盖。App／DMG 仅为本机临时签名，未经 Apple 公证。

## 目标与推荐判断

用户在 Apple TV 使用 Infuse，已登录 Trakt；希望映览显示最近观看、已看状态和续播进度，不要求逐次完整观看历史，也不打算打开 Mac 上的 Infuse。片源可能混用 Emby／极影视、SMB 或 WebDAV，目前未确认。

接入方向为 **Apple TV Infuse → Trakt → 映览**。映览使用用户注册的 Trakt 应用身份，经独立授权后读取数据，不依赖 Mac Infuse 进程或它的本地缓存。真实 Trakt 读取与正式界面已验证；不等同于逐条核验 Apple TV 本地状态。

成立前提：Apple TV 的 Infuse 已启用 Scrobbling，账号授权有效，记录和进度确实已上传。登录 Trakt 本身不能证明这些前提成立。Mac Infuse 不需要打开；尚未上传的 Apple TV 本地数据不能凭空读取，也不能保证补回历史上从未同步的记录。

## 已核实依据

初稿使用 Tavily 定位官方资料，再读取 Firecore 官方文档与 Trakt 官方 API 合约。后续按用户授权完成开发者注册、独立设备码授权和真实同步；没有启动 Infuse 或读取其私有数据库。安装后映览按用户既有设置运行服务器自动更新。

| 依据 | 结论与适用范围 |
| --- | --- |
| [Firecore：Trakt Sync](https://support.firecore.com/hc/en-us/articles/4405098078743-Trakt-Sync)，页面更新于 2026-05-06 | 支持观看历史、未完成条目的播放位置；要求登录 Trakt 并启用 Scrobbling。是否真实上传要按用户账号验证。 |
| [Firecore：媒体服务器连接](https://support.firecore.com/hc/en-us/articles/360006462093-Streaming-from-Plex-Emby-and-Jellyfin)，页面更新于 2026-05-29 | 使用媒体服务器连接播放时可向服务器和 Trakt 同步观看与进度；Infuse 对该连接的已看状态以媒体服务器为准，不从 Trakt 反向拉取已看历史。 |
| [Trakt 官方同步合约](https://github.com/trakt/trakt-api/blob/master/projects/api/src/contracts/sync/index.ts) | 提供经 OAuth 认证的观看历史、已看及播放进度读取入口；进度按最近暂停排序。合约是接口依据，不等于用户实测结果。 |
| [Trakt 进度字段](https://github.com/trakt/trakt-api/blob/master/projects/api/src/contracts/sync/schema/response/playbackItemResponseSchema.ts) | 包含 `progress`（0–100）、`paused_at` 和记录 `id`；这是进度快照，不是本机文件的秒级播放位置。 |
| [Trakt OAuth 指南](https://github.com/trakt/trakt-api/blob/master/projects/developer/src/lib/guides/authentication-oauth.md) | 设备码无需 Client Secret；授权、轮询、刷新走独立认证域名，轮询遵守返回间隔与有效期。 |
| [Trakt 分页变更 #775](https://github.com/trakt/trakt-api/discussions/775)，2026-04-29 发布、05-27 更新 | 已看接口必须分页；剧集的 seasons/episodes 需要 `extended=progress`，不能使用 `extended=full` 假定仍有进度字段。代码和模拟断言已据此修正。 |
| [本项目首页](../../src/home.js)、[条目规范化](../../src/identity.js) | 首页从 `catalog/latest/resume` 缓存读取每条目的最后播放时间；规范化保留 `PlaybackPositionTicks`、`LastPlayedDate`，未保留 `Played`。这里的服务器最近观看不是 Infuse 专属记录，也不是完整观看历史；Trakt 由独立模块读取。 |

旧 Apiary 文档入口本轮返回 502，未将其视为接口失效；改用官方仓库合约。Tavily 的自动摘要曾将整页其他方法的 VIP 提示混入进度查询结论，未据此判断进度读取必须付费。收费限制、应用权限、分页行为以实施时最新官方文档和实际账号响应为准。

## 数据含义与最小范围

| 用户需要 | 实现读取入口 | 展示含义与限制 |
| --- | --- | --- |
| 最近观看 | `GET /sync/history`，并结合进度条目的 `paused_at` | 历史反映已记录的观看事件；未完成条目按最近进度更新时间另列，不能把 `paused_at` 改叫观看完成时间。首版只取最近一页最多 50 个事件，再按作品去重。 |
| 已看状态 | `GET /sync/watched/movies`、`GET /sync/watched/shows` | 按电影／单集保留状态；看过一集不代表整部剧看完。历史第一页不足以还原全量已看状态。 |
| 续播进度 | `GET /sync/playback` | 显示百分比和最近同步时间，不伪造“正在播放”。不同剪辑版时长不同，不能把作品进度直接当某个文件的精确秒数。 |

第一版作为独立的 Trakt 来源展示，读取最近记录和续播，已看按覆盖范围显示。先不与 Emby 或豆瓣自动合并，也不写回远端状态。Trakt 记录可能混合其他播放器和手动标记；在没有来源证据前不能命名为“Apple TV Infuse 专属历史”。

媒体身份使用 Trakt／TMDB／IMDb 等稳定编号及影视类型；单集必须有单集身份或剧集身份加季集号。无法匹配本机片库的条目仍可单独展示，不按标题强行关联。重复读取应幂等；重新观看时允许“曾看完”和“当前有进度”同时成立。

## 真实验证结果与后续检查

已验证正确账号的最近已看、完整分页已看电影／单集、续播百分比，以及正式 App 手动同步和本地展示。设备码、令牌与 Client ID 未输出到 Git，授权在正式配置中加密保存，PixelReel 配置未改。

尚未逐条与 Apple TV 屏幕对照，也未让用户额外播放来测量上传延迟。后续若需要验证新变化，由用户在 Apple TV 正常播放／暂停一个条目，再在 Trakt 更新后手动同步映览；不要自动替用户播放或标记观看。正常读取旧快照成功不保证未来每次 Infuse 上报实时到达。

若记录未到 Trakt，先核对 Apple TV 的 Scrobbling、账号绑定、影片识别及同步错误，不修改映览展示来掩盖上游缺口。若只在媒体服务器有状态，再确认连接类型与同一用户身份；SMB/WebDAV 场景不能假设存在 Emby 回写。

## 后续工程边界

现已新增 Trakt 客户端、凭据生命周期、本机缓存与原生展示，复用 [RateLimiter](../../src/emby.js) 和 [本机加密能力](../../src/store.js)。观看快照独立存放于 `trakt_cache`，海报存于 `trakt_posters`；`settings` 中的 `traktCredentials` 与 `traktPosterCredentials` 分别加密保存授权和海报凭据。没有复用 Emby 的远端身份或把 Trakt 对象硬塞进服务器条目结构。

实际读取记录使用 GET；OAuth 换取／刷新令牌属于必要认证操作。产品承诺只读须由请求白名单保证，不能未经核实宣称 Trakt 授权本身只有只读权限。失败保留带时间的旧缓存；账号切换须隔离数据，未获取完整分页不能覆盖全量已看集合。使用前重新核对官方分页、删除与撤销标记语义。

这一阶段暂不要求跨来源去重、实时在播、自动控制 Infuse、iCloud 私有数据接入、历史补造或向豆瓣／Emby 回写。若用户后来要求其中任一项，需要重新审查业务含义和范围。

## 对推荐路线的对抗性自审

### 🔴 致命弱点

“已登录 Trakt”不等于“可取得用户所需的数据”。有效应用身份、正确账号及实际上传均为必要前提；旧 Client ID 曾被拒绝，现已用新应用完成授权及真实同步。当前已消除这一阻塞，但无法读取未上传的 Apple TV 本地进度。

### 🟡 主要缺陷

| 缺陷 | 后果 | 处理 |
| --- | --- | --- |
| 同一账号混合多个播放器 | 将其他来源误标为 Infuse | 标注 Trakt 来源，不推断设备归属 |
| 历史与进度的时间语义不同 | 未看完被误当已看、暂停被当实时播放 | 分开状态、时间和展示名称 |
| 只有最近历史或部分分页 | 老记录被误标未看、缓存被清空 | 明示覆盖；完整分页后才替换对应集合 |
| 稳定编号缺失或多剪辑版本 | 错配影视、进度对应错误文件 | 独立展示，匹配不足不自动合并 |
| 浏览器沿用其他账号 | 将错误应用列表当作用户账号证据 | 每次授权前明确核对账号；本次纠正后的列表重新验证 |
| 模拟响应滞后于官方契约 | 测试全绿但真实接口没有 seasons | 已核实新分页和 `extended=progress`，保留真实验收门槛 |

### 🟢 改进建议

已完成应用身份、账号和真实数据读取验证；后续需要时再对照 Apple TV 新播放样本，保留更新时间和失败状态。用户目标不要求逐次历史，不建设事件仓库。若用户要求精确到 Infuse 或特定 Apple TV，先取得来源字段证据，再决定能否满足。

### 📋 审查总结

技术路线已通过官方契约、模拟测试和真实账号读取三层验证。剩余边界是上游上传时效、设备归属和真实令牌到期后的长期续期；刷新轮换已做模拟测试，没有提前消耗真实 refresh token。自审由主 agent 完成，未启动子 agent。

## 接手约定

继续前核对目标、设备、Mac Infuse 不启动约束、当前代码、正确账号与应用身份。复用会话中已有授权；本文件不能替代用户授权。不要因旧记录写着“先验证再实现”而忽略后续用户明确要求继续实施。

缺少数据／工具时标记受阻；进入未知区域先说明证据与选择。需要变更数据来源、写回远端、读取 Infuse 私有凭据、合并身份或扩大为完整工程时，交回确认范围。前提被反证时停止受影响路线，提交预期、实际、复现证据、已尝试项、受影响假设及待决定问题，不降低验收标准。

后续启动指令：阅读本文件和 Trakt 使用说明，先读取本机状态，不重复注册应用或授权。保持 Mac Infuse 关闭；仅在用户要求核验新变化或排错时执行必要远端读取，并明确区分缓存、Trakt 上报与 Apple TV 本地状态。
