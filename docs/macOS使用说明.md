# macOS 原生预览版

适用版本：0.1.20；更新日期：2026-10-26。用于体验新首页和原生桌面工作流。采用暖白、浅灰与琥珀色的原生界面，已连接 Trakt 时首页优先显示最近观看与续播海报，可切换查看原有服务器记录。Mac 优先，网页版继续保留；没有修改现有 NAS、TTD、302 反代或其端口。

## 0.1.20：账号配置与导航

「Trakt 观看」右上角有明确的「账号与配置」入口，集中查看当前账号、授权状态、最近同步时间及数据来源；可重新授权／切换账号、断开账号，并展开应用配置和海报来源。查看配置不会修改现有授权，也不会显示已保存的令牌。

顶部导航的「服务器设置」移至最后，导航菜单与快捷键顺序同步调整。

## 0.1.19：首页观看海报

- 首页「最近看过的故事」「还没看完」分别展示最近已看与进度快照；各保留最多 8 部作品，同一部剧只保留最新一集。横向滚动查看更多海报，「全部记录／全部续播」进入完整列表。
- 首页来源可切换「Trakt 观看／服务器记录」，两种来源保持独立；完整 Trakt 列表保留每一集和原有筛选、搜索、分页。
- 图片按电影／剧集 ID 匹配，缓存到本机后可离线显示。首次载入按两秒间隔排队；网络失败显示「重试海报」。不根据片名猜图。
- 「Trakt 观看」右上角「账号与配置」→「海报来源」支持自己的 TMDB API 读取令牌或 API Key，加密保存在本机。配置后优先使用 TMDB；未配置时使用 Trakt 官方图片。保存会清除旧图片缓存并重新载入，不影响观看记录或 Trakt 授权。
- 图片缓存上限 64 MiB，按可见卡片加载；旧观看快照也能按 ID 补图。图片请求使用独立连接池，排队不阻塞列表、状态或取消操作。

## 0.1.18：Trakt 观看记录

顶部「Trakt 观看」独立展示最近已看、全部已看和继续观看。Apple TV 的 Infuse 必须先将记录上传到同一个 Trakt 账号；无需启动 Mac Infuse，也不依赖 PixelReel。

首次使用在「账号与配置」→「应用配置」填写自己的 Trakt Client ID，然后点击「连接 Trakt」，在浏览器核对应用与账号并输入设备码授权。无需 Client Secret；令牌只在本机加密保存。已配置并连接的用户直接点击「同步 Trakt」即可，首版不自动定时同步。

- 最近已看：读取最近一页（最多 50 个观看事件），同一作品保留最新一次，因此列表可能少于 50 条。
- 全部已看：完整分页读取已看电影和单集；看过某一集不代表整部剧看完。
- 继续观看：展示 Trakt 上报的百分比与进度更新时间，不代表正在播放，不提供播放控制。

支持片名搜索、电影／单集筛选和每页 24 条的本地分页；顶部服务器选择不影响 Trakt。只有整次同步完整成功才替换缓存，失败保留旧数据和更新时间。离线模式只查看缓存；任务中可以停止。

「账号与配置」可重新授权／切换账号，或断开并清除本机 Trakt 缓存，后者保留 Client ID，不删除远端观看记录。更换应用配置会清除本机旧授权和缓存；重新授权确认新账号后替换旧数据。所有观看数据请求只读，不写回 Trakt、Emby 或豆瓣。账号记录可能混合其他播放器，不能把它当作 Infuse 专属历史；Infuse 尚未上传的变化也无法立即读取。

## 构建与打开

要求 macOS 14 或以上、Swift 工具链（可使用 Command Line Tools），开发机通过 fnm 安装项目 `.node-version` 指定的 Node 22.22.2。已在 Apple Silicon Mac 验证；构建脚本使用本机架构，不生成通用二进制。

在项目根目录执行：

```sh
scripts/test-macos.sh
scripts/build-macos-app.sh
open dist/EmbyScope.app --args --demo
```

应用内附 Node 及其 LICENSE，运行时无需 fnm、Homebrew 或系统 Node。构建检查 Node 不依赖 Homebrew 动态库。产物为 `dist/EmbyScope.app`，采用本机临时签名；不等同于 Apple Developer ID 签名或公证。`scripts/build-macos-dmg.sh` 会构建并校验 DMG，同时生成 SHA-256 文件；安装与数据恢复见 [安装与备份](macOS安装与备份.md)。

`--demo` 使用独立临时目录、两台虚构服务器和原创封面，禁止外部请求。关闭窗口或按 `⌘Q` 会退出应用、停止辅助进程并清理演示目录。演示中的设置修改和远端更新按钮不可用。

关闭演示后，双击 `.app` 或运行 `open dist/EmbyScope.app` 可进入正式模式。默认直接进入首页，可在「服务器设置 → 打开映览时需要密码」中启用密码保护，然后按需添加自己的连接。密码开关与旧密码处理见[安装与备份](macOS安装与备份.md)。**正式模式添加连接会读取远端；演示模式不含真实账号。** 不要同时运行多个不同副本；相同配置目录有实例锁。

## 页面与数据含义

- **此刻**：顶部为最近有有效最后播放时间的条目；没有有效日期时可展示继续观看但不虚构时间。下方分别展示继续观看和最近观看清单。
- **概览**：第二页保留媒体计数、去重计数、来源状态、媒体库、最近入库和缓存时间。在线状态来自最近同步结果，不是持续探测。
- **片库**：全局服务器筛选、标题搜索、电影／电视剧筛选、每页 24 条。切换来源重置页码，返回页面保留当前结果。顶部状态栏提供缓存时间、问题统计和同步记录入口，详见下方 0.1.15 说明。
- **豆瓣已看**：位于片库之后，独立展示已看记录、个人评分和短评，不随 Emby 服务器筛选。同步、补图和 S3 配置在服务器设置中管理，详见[豆瓣已看说明](macOS安装与备份.md#豆瓣已看)。
- **重复与刮削排查**：分别筛选资源重复线索、元数据疑点与季范围待确认；不同季不直接列为重复候选。打开详情后核对全部连接缓存中的关联记录，当前记录置顶，显示逐对依据及已有资源位置。详见下方 0.1.2 说明。
- **详情**：简介、年份、评分、类型、作品编号、分服务器条目标识和资源位置。位置按需读取并沿用后端权限与脱敏规则；资源路径可能属于容器、STRM 或虚拟目录。电视剧支持季筛选及单集分页。
- **服务器设置**：连接增删改、NSFW 标签、轻量和完整校准周期、自动更新总开关、手动更新、本地状态重读和锁定。所有远端访问仍由后端限速。

顶部眼睛按钮只改变本次会话的 NSFW 展示；每张虚化海报也可单独解除。切换来源、锁定或退出恢复遮挡。遮挡属于显示偏好，图片仍可能加载到内存。

最近观看读取本地 `catalog/latest/resume` 快照中的 `LastPlayedDate`，按时间排序，最多 24 条；一条媒体库记录只有最后一次时间，**不是完整观看历史、不代表已经看完，也不会从入库时间推导观看**。快照仅覆盖接口曾返回且仍在缓存里的条目。轻量更新无法补齐所有已看完且不再出现在继续观看中的作品。各来源缓存时间、离线和权限问题会保留提示。

## 保存、安全与更新

正式配置独立保存于 `~/Library/Application Support/EmbyScope/`，包含 `embyscope.sqlite` 与 `secret.key`。加密和备份边界与网页版一致：需要备份完整目录；拿到整个目录的人仍可能解密凭据。使用[安装与备份](macOS安装与备份.md)中的一致性备份命令，可在应用运行时执行；不要只复制正在写入的单个 SQLite 文件。

不会自动迁移项目 `data/`，也不读取 TTD 凭据。通过内置管理命令导入数据后，使用 `offline-preview` 标记强制离线。已有网页版继续使用自己的目录和端口。桌面监听仅为 `127.0.0.1` 的随机端口，每次启动通过匿名管道传入随机密钥，并始终检查请求来源，启用密码保护时额外要求管理员会话；随机端口本身不承担认证。不会把启动密钥放入命令行、环境变量或日志。

自动更新默认关闭，保存值会跨重启保留。切回窗口不会扫库或重新启动内核；界面保留内存中的当前数据。设置页的手动更新由后端请求远端；顶部「刷新本地快照」、`⌘R` 和设置页「重新读取本地状态」只重读本地缓存，用于查看同步结果。片库列表和概览不会定时重读；片库状态栏、同步记录和设置页的状态轮询只读取本机，豆瓣页在任务运行时也会重读本地进度。首页「正在观看」的前台轮询由独立的「实时查看」开关控制，见下方说明。

开启自动更新后内核可以同步，片库列表和概览仍需重读本地状态才能显示最新快照。关闭自动更新不等于断网：详情、未缓存海报、新连接初始化、手动更新和已开启的实时查看仍可能读取远端。

动效仅为短暂入场、悬停和面板过渡，没有持续动画计时器；遵循系统减少动态效果，并提供应用内开关。海报使用懒加载和解码缩略图，内存图片缓存目标为 24 MiB、64 张；这不是整个应用的内存硬上限，当前显示的图片和 Node 查询也占内存。

## 关联反代

在「服务器设置」点击某台服务器的「关联反代」，填写完整 HTTP / HTTPS 地址。原服务地址和反代地址共用同一个服务器标识、片库和统计，不新增服务器。保存、修改、清空关联不会触发登录、同步或访问反代；这项本地关联在离线预览中也可修改。已登记的地址不能再归属另一连接；系统不会猜测 DNS、不同路径或其他未登记地址是否指向同一服务。

片库继续从原服务读取；反代地址当前用于保存关联关系，**不会自动读取 TTD 日志，也不会向该地址发送媒体账号令牌**。网页版编辑连接也支持这一字段，旧客户端不提交字段时保留原值。

首页「正在观看」支持「读取一次」和可选的「实时查看」，仅访问原服务，按登录 UserId 筛选。当前读取周期、异常提示和极影视兼容检测见下方说明；历史接口验证见[验收记录](macOS验收记录.md)。不会以 302 请求替代正在播放，也不会因接口不可用自动改动原有反代配置。

## 重复与刮削排查（0.1.2）

此页替代原“同作品对照”，默认列出需要核对的记录组。作品统计仍按整部电影 / 整部剧的有效编号归组，与重复资源排查分开。

- **资源重复线索**：同编号电影的多条记录，或同剧的已知季范围有重叠；这不证明单集或文件内容相同。
- **元数据疑点**：关联编号冲突、去掉明确季号后标题仍有差异、同编号电影年份不同、标题季号与已有季集缓存不一致。译名、版本差异也可能触发，请人工核对。
- **季范围待确认**：缺少足够季信息或季号证据冲突；不默认第一季。
- **全部关联（含不同季）**：保留作品关系供查阅；季范围无重叠的正常多季收藏不会仅因此进入默认排查列表。

详情保留每条记录的完整标题、年份、简介、季范围证据、外部编号、来源与 ItemId，展示已有位置缓存。展开“逐对核对依据与位置线索”可看具体哪两条记录有疑点。相同路径在不同服务器上不能证明文件相同；同服务器路径重合也可能只是重复入库。不同路径可能是版本差异、映射或 STRM，不能直接证明多存了一份视频。

排查和筛选只使用本地缓存，不启动全库扫描、远端播放或文件哈希读取。现有“读取资源位置”操作仍遵守离线与限流策略。共享有效编号形成作品关联；缺号或不同编号另有下节的补充线索，但仍不能发现所有刮削错误；没有文件 / 云盘对象身份的证据，不输出“已确认重复文件”结论。

## 编号未关联线索（0.1.3）

排查页新增“编号未关联线索”筛选，补充 0.1.2 只能关联共享有效编号的限制。两种额外依据仅用于核对，不参与片库作品合并或去重计数：

- 同媒体类型、完整标题和有效年份相同，但编号不同、缺失或无法连通。保留季号和标点，不进行模糊片名匹配；同名同年也可能是不同作品。
- 同一服务器、同媒体类型的条目，在已有安全资源缓存中报告了完全相同的媒体文件路径文本。只接受当前格式、无错误缓存和常见媒体文件 / STRM 扩展名；不通过目录或跨服路径连组，不确认文件存在或存储身份。旧时间缓存明确标旧。

详情展开逐对依据可看为什么关联；仅经第三条记录间接连通时，不推定这两条相同。路径、简介、编号仍逐条保留供人工核对。新读取位置后重新打开详情 / 切换排查筛选会重新计算本地证据。

本版不补读远端资源路径、不扫描 NAS。缺年份、片名不同且无可用位置缓存的错刮仍可能漏查；不保证找全重复资源或刮削错误。

## 退出离线预览（0.1.4）

「服务器设置」会明确显示当前模式。离线预览时自动更新开关不可用；点击「退出离线预览…」并确认后，解除持久离线标记，无需重启，自动更新仍保持关闭。退出操作本身不更新远端；之后手动轻量更新、详情或缺失海报可能按需联网。

退出需要桌面连接校验及明确确认；开启密码保护时须先解锁。若配置目录不可写，界面显示错误并继续离线。演示模式、通过启动参数强制离线的测试进程不能通过此接口解除。重复退出不会覆盖用户后来修改的自动更新选项。

打开自动更新，总开关也会启用各服务器已设置的完整校准周期；只想定时轻量更新时，请先把各服「完整校准」设为关闭。尚无片库缓存的连接仍需首次完整建库，具体调度见 [README 更新策略](../README.md#更新策略与重复条目)。

## 实时查看与极影视兼容检测（0.1.8）

首页「正在观看」支持两种来源。普通 Emby 保持默认会话读取：显示当前账号的片名、播放器、设备和服务端上报进度。对于极影视，在该服务器名称旁勾选「兼容检测」，再开启「实时查看」。两个开关默认关闭，不随重启保存，也不启用片库自动更新；不必改播放器地址或 TTD 配置。

兼容检测通过当前账号最多 18 条续播记录的连续变化，显示片名和以下状态：

| 提示 | 含义 |
| --- | --- |
| 观察中，等待连续样本 | 首次读取、重新进入前台或中断后正在建立基线 |
| 检测到播放活动 | 至少连续两次观察到合理的位置前进及播放时间变化，是活动线索，不是确定的播放状态 |
| 未检测到播放活动 | 在观察范围内近期没有新的活动线索，不等于所有播放器都已停止 |
| 状态未知 | 读取失败、权限不足、数据缺失、条目消失或快照过期，不能据此判定是否在播 |

普通模式前台约每 10 秒读取；任一服务器勾选兼容检测时，本次前台轮询约每 15 秒加请求耗时读取。每台兼容请求间隔不少于 15 秒，共用外部服务至少 2 秒限流；失败后至少退避 60 秒，不立即重试。每次最多 18 条、响应最多 1 MiB，不翻页、不扫库。切到后台、离开首页、锁定或关闭实时查看后不再发起新请求；已发出的请求可能在超时前完成。

通常需要至少 30 秒及三次有效样本识别活动。约 60 秒没有新的活动线索后结束提示；暂停和退出不区分。重新进入前台会重新观察，旧快照不会被当成新样本。单击「读取一次」不会启动定时器，单个样本不足以识别活动；实时查看期间此按钮禁用，避免打断观察。

兼容检测不显示进度条、设备或“播放中／已停止”等确定结论。列表外条目、刚开始或即将看完的内容可能不在续播列表，离线同步也可能产生变化，不能保证找全全部播放。数据源目前只在 VidHub 做过真实取样对照，其他播放器和原生极影视 App 未验收；应用识别逻辑经过脱敏样本重放，不能冒充全部客户端实机测试。

检测仅访问原服务器，凭据在后端请求头内；不访问关联反代、TTD 管理接口或 NAS 系统接口，不改媒体数据。观察基线只保留在内存，SQLite 仅保存必要的展示快照；兼容快照超过 35 秒没有刷新时显示未知，普通会话快照仍为 60 秒。

## 0.1.15：片库状态、问题入口与同步记录

原有菜单和操作保留。片库及重复排查页上方显示当前服务器范围、自动更新状态、各服完整片库的最后成功读取时间。服务器状态每五秒从本机读取；“刷新统计”只重新分析缓存，不会发起远端同步。轻量更新不会改变完整片库成功时间。

“资源重复线索 / 元数据疑点 / 待确认”统计当前服务器全部缓存中的关联组，类别可能重叠，不是文件数量，也不受当前片名或类型搜索限制。点击进入原有排查页对应筛选，并清空片名、类型和分页；保留服务器范围。无缓存显示“未读取”，部分缓存显示覆盖范围。

片库状态栏和服务器设置都可打开“同步记录”。从此版本起记录连接初始化、手动/自动轻量与完整校准，以及自动季集补齐；显示开始时间、来源、结果、耗时及各类读取数量。失败、部分完成、暂停、退出中断分开显示；中断持续时间未确认。已有缓存时间不会补造成过去的任务。全局保留最近 2,000 次（运行中的任务不会被清理），窗口展示当前范围最近 100 次。只保存固定原因和状态码，不保存请求凭据或文件路径。删除连接会删除对应本机记录。

豆瓣同步和海报补全仍使用各自原有状态入口，此窗口不包含播放历史、远端 TTD 日志或清理日志。尚未加入缺集检查、版本比较和自动清理。

## 0.1.16：豆瓣同步自动接续补图

全量或增量同步成功保存记录后，自动补全本次同步涉及的缺图，并将图片保存本地；已配置 S3 时同时上传。增量只处理本次日期范围内的记录，不顺带补整个旧库。已有本地图片不重复下载，尚未上传的图片可继续上传。

已看同步和补图分别显示结果。补图失败不会回滚短评、评分或同步进度；可在设置的“海报补全与存储”查看错误或停止任务，再通过“补全缺失海报”重试。豆瓣页在任务进行时读取本地进度；列表与缺图占位的自动刷新在 [0.1.17](#0117同步后的列表与海报自动刷新) 完善，具体行为见下节。来源没有匹配图片或限制访问时仍可能缺图，记录同步成功不表示海报全部成功。

## 0.1.17：同步后的列表与海报自动刷新

豆瓣页保持前台时，正在同步或补图的任务每五秒读取一次本机状态。记录提交后自动刷新当前列表，新增记录、补充短评及匹配数量随之更新；保留搜索条件、类型和页码，只有更换筛选条件才回第一页。处于后续页时，新记录仍按标记日期出现在对应页，不强制跳转。

补图时，图片逐张保存后自动替换缺图占位，已经显示的海报不因缓存数量增加而重复读取。离开豆瓣页、切到后台或锁定后停止该页轮询，回到前台重新核对；同步和补图后台任务本身继续执行，停止任务仍在同步设置操作。任务结束停止轮询。状态读取失败保留已有内容并显示“重试状态”，不会静默假装仍在更新。
