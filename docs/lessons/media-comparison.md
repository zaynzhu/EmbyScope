# 作品归组与资源重复必须分层

**结论速览：**作品统计用类型与有效外部编号保守归组，排查页另做季范围与逐对证据；“多条记录”不能改写为“存了多份文件”。
**适用条件：**映览0.1.2起的排查模型，0.1.3起含编号未关联线索；只读缓存，不具备文件哈希或云盘对象身份验证。

## ✅ 统计去重与人工排查使用不同判定（2026-10-23）

- **环境：**Node22.22.2 / SQLite / SwiftUI，0.1.10回归通过。
- **为何值得记：**同剧不同季曾被界面表述成重复；用户真正需要的是反查多份资源和错刮线索，整剧归组不能直接满足该目标。
- **最终方案：**沿用 `groupWorks` 与 `comparisonGroups` 两条独立路径。回归中已执行的最小案例原文如下，来源 [comparison.test.js](../../test/comparison.test.js)：

```js
const first = series('1', '科拉传奇 第 1 季')
const second = series('2', '科拉传奇 第 2 季')
const separate = comparisonGroups([first, second])[0]
assert.deepEqual(separate.comparison.counts, { candidate: 0, distinct: 1, unknown: 0 })
assert.equal(matchesReview(separate), false)
assert.equal(matchesReview(separate, 'all'), true)
```

- **为什么这样做：**整剧外部编号可相同，但季范围不重叠时属于不同季收藏；缺季号不能默认第一季，标题与结构化信息冲突时保留疑点。编号冲突组件可用于排查但不强行计为一个作品。
- **适用条件：**内部 ItemId、UserId 必须在服务器作用域内使用；路径也只在同服、同类型且安全缓存有效时形成文本重合线索。
- **验证证据：**上述测试以及 [identity.test.js](../../test/identity.test.js)、[app.test.js](../../test/app.test.js) 覆盖不同季、同季多条、未知季、传递编号冲突、跨服相同ID、同路径与分页。0.1.10全量74项Node测试通过。
- **关键步骤：**归组统计 → 独立计算逐对季范围/元数据依据 → 显示每条来源、原始字段、时间与位置线索 → 由用户人工核对。完整界面定义见 [使用说明](../macOS使用说明.md) 0.1.2/0.1.3节。
- **易错点：**3条记录可有3对候选，候选对数不等于3个重复文件；同名同年仅补充排查，不改变去重计数。跨服相同路径既可能同一挂载也可能不同主机，不能断定相同文件。
- **交叉验证：**本轮单agent核对代码、既有测试输出与 [设计审查](../设计审查.md)；历史人工缓存验收见 [macOS验收记录](../macOS验收记录.md)。未宣称NAS物理文件已确认重复。

## ⛔ 用“同作品对照”暗示同季重复或已经确认多份文件（2026-10-23）

- **环境/交叉验证：**映览早期整剧归组界面；用户反馈与后续单agent回归记录。
- **报错原文：**无异常堆栈；原界面措辞为“同作品对照”，用户反馈“不同季”被理解成“同一季然后重复”。
- **稳定片段：**`同作品对照`、`季范围待确认`、`candidate`。
- **错误原因：**计数实体和展示承诺混淆；没有足够证据就把作品、媒体库记录、季、实际文件视为同一层。
- **为何不可再采用：**仅改显示文案而保留不同季进入默认重复清单，仍会误导删除决策。缺路径时也不能补造文件数量。
- **替代方案：**使用本页成功条目的分层模型，显示“重复与刮削排查”和逐对依据。
- **判定时效：**针对以整剧为单位的编号体系；未来即使取得文件身份，也应单独标记证据强度，不能反向污染作品统计。
