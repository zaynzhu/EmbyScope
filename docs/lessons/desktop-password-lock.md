# 桌面免密码与认证边界

**结论速览：**仅桌面启动密码默认关闭，SQLite持久化开关；启动密钥、Host、来源校验和凭据加密始终保留，网页认证不跟随关闭。
**适用条件：**用户明确要求的Mac个人自用版本0.1.10；旧桌面数据同样默认免密码，不能无授权推广到其他项目或网络服务。

## ✅ 把便利性开关与进程认证分开（2026-10-23）

- **环境：**Node22.22.2 / SQLite / SwiftUI；同Mac当前用户的本地辅助进程。
- **为何值得记：**直接移除共享后端登录检查会影响网页版；只隐藏Swift登录界面又无法通过后端认证。
- **最终方案：**[server.js](../../src/server.js) 中以下策略在桌面密钥验证之后使用；完整实现、接口和限流以代码为准。

```js
const passwordRequired = () => !desktopKey || store.db.prepare("SELECT value FROM settings WHERE name='desktopPasswordRequired'").get()?.value === 'true'
```

- **为什么这样做：**没有desktopKey的网页进程永远要求密码；有有效桌面密钥时才允许默认免启动密码。开关独立持久化，保留已有密码哈希；开启时新建密码或验证旧密码，失败不改变设置。新密码界面要求重复输入，关闭后隐藏手动锁定，重新开启仍验证旧密码。
- **关键步骤：**启动先取认证状态 → 免密码时加载本地首页 → 在设置明确开启并验证 → 切换使旧会话失效并签发当前会话 → 重启或手动锁定后必须登录。离线模式也允许修改本地密码开关，不请求Emby。
- **验证证据：**[desktop-lock.test.js](../../test/desktop-lock.test.js)覆盖默认、新旧数据、重启持久化、退出、错误密码、限流、来源和网页版；Swift测试覆盖失败保留状态和免密码锁定不清屏。保留输出原文为 `# tests 74`、`# pass 74`、`# fail 0`，Swift `24 tests in 2 suites passed`。真实UI确认默认入首页、开关关闭、开启弹窗、空值禁用确认、取消保持关闭；没有在UI设置用户密码。
- **易错点：**旧强制认证测试应显式准备“密码锁开启”场景，不能删除401断言。开关不是磁盘加密，也不抵抗可读写当前用户配置目录的人；旧密码保留不等于自动启用锁。
- **交叉验证：**单agent实现前 [红队自审](../desktop-password-review.md)、74项Node与24项Swift回归、原生UI检查；没有多agent审查。操作说明以 [安装与备份](../macOS安装与备份.md) 为权威。

## ⛔ 新默认值下仍把所有桌面请求都期待为401（2026-10-23）

- **环境/交叉验证：**0.1.10第一次全量回归，单agent读原始输出后修正测试前提，最终全量通过。
- **报错原文（当轮工具输出保留片段）：**

```text
Expected values to be strictly equal:

200 !== 401
```

- **稳定片段：**`200 !== 401`；失败位于 `test/home.test.js` 与 `test/offline-mode.test.js` 的旧桌面认证场景，不记录随编辑变化的行号。
- **错误原因：**产品已明确默认免启动密码，两个历史测试未设置开启状态，前提不再成立；这不意味着可以移除启动密钥校验或取消所有认证测试。
- **为何不可再采用：**机械改期望为200会丢失锁开启时的保护覆盖；只跑新测试也会遗漏旧场景。
- **替代方案：**旧强制认证场景预置 `desktopPasswordRequired=true`，继续断言401；新测试独立覆盖默认免密码与网页不变。
- **判定时效：**仅0.1.10的明确产品变更；其他200/401差异仍需排查真实认证漏洞，不能照抄此归因。
