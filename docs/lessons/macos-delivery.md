# macOS 构建、安装包与隔离预览

**结论速览：**构建App、更新Applications与生成DMG分别验收；用户只想先看效果时，直接打开独立离线预览，不覆盖正式App。
**适用条件：**macOS14+ / Apple Silicon / fnm Node22.22.2 / SwiftUI，0.1.10；当前仅临时签名，跨机器Gatekeeper和公证未验证。

## ✅ 交付要验证包内版本，预览要隔离配置与网络（2026-10-23）

- **环境：**上述本机构建环境，SQLite业务内核作为子进程随包分发。
- **为何值得记：**曾只更新App而遗漏DMG，导致安装包仍是旧版；还需区分“从磁盘映像运行”和“隔离预览”。
- **最终方案：**以下是本对话实际执行的命令；DMG脚本内部先构建App，完整安装/备份步骤仅在 [安装与备份](../macOS安装与备份.md) 维护。

```sh
scripts/test-macos.sh
scripts/build-macos-dmg.sh
```

- **为什么这样做：**版本号从包内Info.plist提取，打包包含独立Node运行时、资源、Applications链接和中文说明。镜像生成后还需校验SHA-256、只读挂载核对版本/build、签名、可执行文件和后端源码一致性，不能用构建exit0替代最终包验收。
- **验证证据：**本轮重新读取保留输出：`Test run with 24 tests in 2 suites passed`；`hdiutil: verify: checksum ... is VALID`（临时路径省略）。对话已完成0.1.10/build11只读挂载与SHA-256检查，详见 [macOS验收](../macOS验收记录.md) 0.1.10节。本地输出位于 `test-output/password-swift-tests.log`、`test-output/dmg-0.1.10-build.log`，非可移植依赖。
- **关键步骤：**测试 → 构建/签名 → DMG生成与校验 → 挂载检查 → 明确是预览还是安装。0.1.10预览使用新的bundle标识、独立SQLite与密钥、本地只读缓存副本，不复制账号令牌，强制offline并拒绝外部fetch；正式数据未改。
- **易错点：**正式App从DMG直接运行仍使用正式配置，可能按原设置联网；同bundle已有实例会被激活，不能把旧窗口误当新版。退出前不要覆盖正在运行包。数据复制要用SQLite一致性备份，不能只拷贝运行中的主库漏掉WAL。
- **交叉验证：**单agent自动测试、构建与原生界面核对；[桌面路线审查](../plans/macOS桌面版路线.md)记录原生界面复用业务内核的取舍。未做多agent精粹认定。

## 🔶 长期常驻和跨机器分发（2026-10-23）

- **环境/交叉验证：**本机短时间采样，单agent原始验收记录；0.1.10未重新测长期内存。
- **当前推断：**原生界面加本地业务内核可运行，不能据短测断言长期无增长或任意Mac无需安全提示。
- **已到哪一步：**此前已有真实缓存短时内存与退出回收采样；当前包为arm64临时签名，未做Developer ID公证。
- **下一步验证动作：**用户要求长期验收时复用 [macOS验收](../macOS验收记录.md) 的冷暖缓存/翻页/静置/退出指标；跨机分发另做签名、公证、Gatekeeper验证。不用关闭系统安全保护作为修复。
- **为何值得继续：**常驻负载和可分发性是两个独立验收项，不能由UI好看或本机能启动推导。

## ⛔ App更新成功但DMG仍旧（2026-10-23）

- **环境/交叉验证：**0.1.9首次界面交付，单agent文件检查；用户指出交付遗漏。
- **报错原文：**无构建错误；实际文件检查发现“最新的 DMG 还是 0.1.6”，当时只构建安装了0.1.9 App。
- **稳定片段：**`build-macos-app.sh`、`build-macos-dmg.sh`、`CFBundleShortVersionString`。
- **错误原因：**将构建与本机安装误当成生成分发镜像；两个脚本职责不同。
- **为何不可再采用：**用户打开旧安装包看不到新功能，还可能覆盖成旧版。
- **替代方案：**本页成功条目的独立DMG验收；交付链接指向核验过的精确版本。
- **判定时效：**当前脚本分工；自动化流程改变后重新核对产物链。
