# Trakt 观看记录与海报接入

**结论速览：**用独立 Trakt 设备码授权读取三个观看集合；图片按电影／剧集 ID 从已配置的 TMDB 获取并缓存本机，图片与普通请求分连接池，不能把接口成功当成海报已显示。
**适用条件：**本机 macOS / Apple Silicon、fnm Node 22.22.2、SwiftUI（应用要求 macOS 14+），映览 0.1.18–0.1.20；Infuse 已向同一 Trakt 账号上传记录。真实上传延迟与长期令牌续期仍待验证。

证据范围：单主 agent 实施、自审、模拟测试及真实窗口验收，没有多 agent 交叉审查，不标“精粹”。本次为历史回填：代码、测试和保存的测试日志已重新核对；图片探测输出从本会话可见的原始工具结果摘录。早期授权阶段未保留在当前上下文中的原始输出不补写，结论引用当时提交的验收记录。

本库纳入 Git，不保存用户名、私人片名、Client ID、令牌或凭据文件绝对路径。配置由用户在「Trakt 观看 → 账号与配置」管理；已保存凭据位于本机加密配置中，完整备份方法见[安装与备份](../macOS安装与备份.md)。

## ✅ 先分清账号、应用与观看集合，再提交完整快照（2026-10-26）

- **环境／适用条件：**上述 macOS / Node 22.22.2 / SwiftUI，Trakt API v2；独立应用已获准、设备码授权完成，账号资料与用户指定身份一致。
- **为何值得记：**浏览器已登录不等于账号正确，旧应用配置不等于仍然有效；历史第一页、全部已看和暂停进度也不是同一个数据集。混淆这些条件会把错误账号或不完整结果当作同步成功。
- **最终方案：**沿用 [TraktService](../../src/trakt.js) 的认证域、只读白名单、独立缓存与事务提交。以下为已执行的相关模拟验证命令原文，在项目根且已启用指定 Node 版本时运行：

```sh
node --test test/trakt.test.js
```

- **为什么这样做：**设备码不需要 Client Secret；OAuth 走 `auth.trakt.tv`，观看数据走 `api.trakt.tv`。最近历史仅取一页，全量已看必须验证分页，剧集已看用 `extended=progress` 获取季集；续播是百分比快照，不能宣称实时在播。刷新令牌轮换后先加密持久化，再继续读取。
- **关键步骤：**先读本机连接状态 → 必要时核对正确账号并授权 → 验证完整分页及字段 → 全部集合成功后原子替换 → 界面核对时间、季集与进度。失败保留旧缓存；换账号取消旧任务，旧响应不能回写。
- **验证证据：**[0.1.18 验收记录](../macOS验收记录.md)记录真实授权、首次读取、正式 App 再同步和翻页通过；快照为最近 48、已看 3835、续播 20，数字只代表当时样本。当前[模拟测试](../../test/trakt.test.js)覆盖分页不完整、轮换、取消、离线、限流及本机认证。
- **交叉验证：**单主 agent；方案自审见[接入路线](../plans/Infuse观看记录接入路线.md)，不是独立审计。早期原始授权日志未在本轮重读，不据此推断旧应用消失原因。
- **易错点：**只读是程序的 GET 白名单约束，不代表 OAuth 授权范围本身只读；Trakt 账号可能混合其他播放器记录，不能标成某台 Apple TV 专属历史。入口应显示实际账号、授权状态、数据来源和同步时间，不能只让用户看到一个无文字的齿轮。

完整配置和操作步骤只维护在[使用说明](../macOS使用说明.md)，不要为复用经验再次注册应用或重新授权。

## ✅ 图片独立按 ID 补齐，TMDB 读取令牌使用 Bearer（2026-10-26）

- **环境／适用条件：**上述环境，映览 0.1.19–0.1.20；用户已授权使用自己的 TMDB 图片配置，Trakt 可返回准确跨服务 ID。
- **为何值得记：**记录同步成功后仍整页无图；真实图片节点又拒绝下载。仅加卡片或依赖模拟图片不能解决这条完整链路。
- **最终方案：**复用 [TraktPosters](../../src/trakt-posters.js)：电影使用电影 TMDB ID，剧集使用剧的 TMDB ID；旧快照缺剧 ID 时按 Trakt 剧 ID 查询摘要。凭据类型分流的已验证实现原文为：

```js
if (token.includes('.')) headers.Authorization = `Bearer ${token}`
else url.searchParams.set('api_key', token)
```

- **为什么这样做：**本次已有凭据是 TMDB API 读取令牌，不能当成 v3 API Key。身份由类型与 ID 确认，片名不参与猜测；图片节点只收到图片请求，不携带 API 授权。
- **关键步骤：**核对作品身份 → 请求详情获取图片路径 → 下载并验证域名、重定向、体积及文件签名 → 缓存本机 → 原生解码显示 → 离线再次展示。远端同服务请求间隔至少两秒；同剧去重下载，只按可见作品加载。
- **验证证据：**本会话真实探测先以 Bearer 获取公共电影详情，再下载其图片，工具输出摘录如下（不是外部错误正文）：

```text
{ status: 200, validId: true, posterAvailable: true }
{ imageStatus: 200, mime: 'image/jpeg', bytes: 103530 }
{ total: 14, saved: 14 }
```

  最后一行来自后续首页涉及作品的逐个下载验收。隔离离线窗口及正式安装窗口均显示真实海报；不是仅凭 HTTP 200 推断可显示。[测试](../../test/trakt.test.js)同时覆盖精确身份、离线缓存、去重下载、拒绝伪图片与取消回写。
- **交叉验证：**单主 agent，真实接口与原生窗口两层验证；前提修正见[设计审查](../设计审查.md)“Trakt 首页与海报”，交付证据见[0.1.19 验收](../macOS验收记录.md)。
- **易错点：**单集 TMDB ID 不能用来请求整部剧的海报；未配置 TMDB 时仍可能遇到 Trakt 图片访问失败。缓存成功的 14 张不证明所有已看条目都有图。官方要求 Trakt 图片缓存，不能让界面直接热链；接口政策依据见项目设计审查引用的官方文档。

## ✅ 图片排队不能占住列表与状态的连接（2026-10-26）

- **环境／适用条件：**上述 macOS / SwiftUI 环境；URLSession 每主机连接数有限，图片需经过远端限流才能返回。
- **为何值得记：**真实预览出现海报加载期间首页延迟切换、部分卡片暂不可用；普通 API 与图片共用连接池，排队会放大页面等待，不能全部归因于上游无图。
- **最终方案：**[APIClient](../../desktop/Sources/EmbyScopeCore/APIClient.swift)为图片使用独立 `imageSession`，图片读取超时 90 秒，普通请求保持 30 秒；[PosterCache](../../desktop/Sources/EmbyScopeApp/DesignSystem.swift)共享图片任务并解码缩略图。没有降低外部服务限流。原生验证命令原文：

```sh
scripts/test-macos.sh
```

- **为什么这样做：**本机请求也会等待远端队列；状态、列表、取消操作应有可用连接，不应排在图片后面。只有界面实际读取新快照才能展示，后台打开窗口时前台任务尚未执行，不等于授权丢失。
- **关键步骤：**先区分本机快照、图片任务及前台状态 → 分离连接池 → 核对普通列表切换 → 核对图片显示及离线缓存。首页按剧聚合，完整列表保留单集，避免为了排版丢失观看语义。
- **验证证据：**本轮重新读取保存的 Swift 日志：`Test run with 41 tests in 2 suites passed`；后端日志：`# tests 125`、`# pass 125`、`# fail 0`。真实新版窗口显示首页海报、续播百分比、完整网格，并能切回服务器来源。测试数量是当时基线，不是以后固定断言。
- **交叉验证：**单主 agent；[0.1.19–0.1.20 验收记录](../macOS验收记录.md)与[原生竞态测试](../../desktop/Tests/EmbyScopeAppTests/AppModelTests.swift)。未测长期网络拥塞下的延迟分位数，不宣称永不超时。
- **易错点：**预览副本可能未激活；先核对前台状态再判断数据缺失。发行、安装和隔离预览是不同产物，继续遵守[macOS 交付经验](macos-delivery.md)，不要将含模拟注入或真实配置的副本作为安装包。

## ⛔ 有 Trakt 图片地址就当作图片可下载（2026-10-26）

- **环境／交叉验证：**macOS / Node 22.22.2，单主 agent 的真实网络探测；来源为本会话 `fetch` 包装器打印的响应信息及 curl 输出。
- **报错原文：**回看可见原始工具输出摘录，未重新发起请求：

```text
{"host":"media.trakt.tv","status":403,"type":"text/html; charset=UTF-8","location":null}
Trakt 海报暂不可用
curl: (28) Connection timed out after 25006 milliseconds
000  0
```

  403 对应 API 返回的图片地址；curl 超时对应官方文档中的 `walter-r2.trakt.tv` 示例地址，两者不是同一请求。
- **报错稳定片段：**`403`、`text/html`、`Trakt 海报暂不可用`、`curl: (28) Connection timed out`。
- **错误原因：**已证实“元数据返回地址”和“图片下载成功”是不同条件；具体 403 风控规则、超时网络根因未核实，不能断言永久封禁或某个时段必然恢复。
- **为何不可再采用：**在同样访问失败的网络下，直用返回 URL 仍会得到空海报；添加模拟成功响应不能证明修复。
- **替代方案：**使用上方按 ID 读取 TMDB 并缓存的成功路径；若无已授权图片配置，明确占位及重试，不伪造图片。
- **判定时效：**2026-10-26 本机网络与节点响应；网络、节点、政策变化后可重新验证，不能泛化成 Trakt 图片服务整体不可用。

## ⛔ 把 TMDB Bearer 读取令牌放进 api_key（2026-10-26）

- **环境／交叉验证：**macOS / Node 22.22.2，单主 agent 同一凭据、同一公开详情请求的真实对照。来源是本会话脚本打印的校验摘要，凭据未输出。
- **报错原文：**

```text
{ status: 401, validId: false, posterAvailable: false }
```

- **报错稳定片段：**`status: 401`、`validId: false`；这是本地探测输出，不是 TMDB 原始错误正文。
- **错误原因：**配置名虽叫 `TMDB_API_KEY`，实际值是 API 读取令牌；改用 `Authorization: Bearer` 后同一详情及图片成功。不能只看变量名判定认证形式。
- **为何不可再采用：**读取令牌作为 `api_key` 查询参数不会自动变成 v3 API Key；不可据这次 401 宣称账号或全部凭据失效。
- **替代方案：**上方成功条目的认证分流；在应用中独立加密保存，不将凭据提交到源码或打入安装包。
- **判定时效：**2026-10-26 的 TMDB 认证形式；更换凭据类型或 API 后核对当前契约。
