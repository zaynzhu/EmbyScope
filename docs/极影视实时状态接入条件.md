# 极影视实时状态接入条件

状态：历史改造备选，用户已拒绝下述两条路线，尚未接入。2026-10-23。

截至 2026-10-23，已验证的接口未提供明确的极影视在播状态；用户随后接受兼容活动检测，0.1.8 已接入，操作及限制见[使用说明](macOS使用说明.md#实时查看与极影视兼容检测018)，实测依据见[验证路线](plans/极影视播放状态验证路线.md)。兼容检测只提示观看记录活动，不能确定暂停或退出。本文保留精确状态出口的历史备选，不得继续要求用户从下述两条路线中选择。

## 已确认的缺口

极影视能登录、读取媒体并经现有 TTD 反代完成 STRM 直链播放，但已保存账号读取两种标准会话查询路径均返回 404。容器日志出现周期性 Progress POST、响应 204，缺少正文及规则归属，不能据此取得影片和进度。

TTD 现有实时看板绑定原 Emby。运行版公开接口及插件协议尚未确认支持按极影视反代规则读取实时状态，详见 [排查记录](TTD兼容排查.md)。

## 优先路线：TTD 提供经过认证的状态出口

前提是 TTD 作者或能够维护其运行实现的人愿意支持。这样可以保留现有客户端地址与播放路径。以下为需求草案，不是已有接口，也没有对外发送：

- 观察原反代处理的开始、进度、停止事件，绑定反代规则、已验证用户、设备和会话；不能直接信任正文 UserId，不能按用户名跨服合并。
- 最小状态字段：规则、用户、会话/设备、媒体标识，实报位置、暂停状态、接收时间。标题和总时长可使用已有元数据，缺失则未知，不主动扫库。
- 保留原身份校验、请求正文、上游响应和 302 行为；被拒绝请求不得生成有效状态。状态记录失败不得让正常播放失败，内存和保留数量有上限。
- 成功响应仅表示观察到上报，不声称媒体服务已持久保存。停止结束对应会话；约 60 秒无新上报则过期/未知，暂停也遵守新鲜度限制，不用墙钟外推进度。
- 出口认证应仅限状态读取、可撤销并限制规则/用户范围，不返回 Token、Cookie、签名直链或原始报文。现有 OpenAPI Token 具有管理员权限，不能当作受限凭据。

映览取得可验证的出口后再添加适配，反代仍关联原服务器连接。沿用默认关闭的前台实时开关、10 秒刷新、失败退避与过期提示，不改变片库同步设置。

## 备选路线：独立测试入口

如果无法修改 TTD，可另行设计独立入口，由一个测试客户端显式经过它，再转发到原极影视反代。此路线会改变该客户端地址并增加播放依赖；当前未实施，用户批准前不部署、不选 NAS 端口、不改客户端。

风险必须明确：新入口中断会影响经过它的客户端，采集故障隔离不等于入口整体不会影响播放。必须验证认证、正文及响应转发、重定向和媒体请求边界，不向匿名请求注入固定令牌，不意外代理整部视频或改变上游行为，也不能让常驻 Mac 成为所有设备播放的强制依赖。

保留既有入口供客户端随时切回。原生极影视或直接访问原服务的播放器如果不经过观察入口，便不在覆盖范围。此路线只是待审查备选，不能承诺所有播放器均可见。

## 验收条件

1. 两服同时播放，规则、用户、设备和媒体不串数据。
2. 实际客户端测试播放、拖动、暂停、恢复、停止；显示最近实报位置，不把一次客户端成功推广到全部播放器。
3. 断网或不再上报后标记未知，缺失不当零，旧事件不覆盖新会话。
4. 未授权访问拒绝，响应及日志无凭据，失效或取消接入不改原反代配置。
5. 分别验证原 STRM 302 行为与实时显示，一项通过不能替代另一项。
6. 真实请求范围和次数另经用户确认，本文不触发 NAS 请求。
